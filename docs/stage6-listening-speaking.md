# 6단계: 소리·말 나래(듣기·말하기) 설계

작성: 2026-11-09 (계획·검수 Opus, 구현 Sonnet — `CLAUDE.md` 작업 분담)

## 원칙

1. **학생의 목소리·얼굴을 모으지 않는다(결정 6·8).** 1·2차는 녹음·카메라 없이 만든다. 듣기 자료는 **기기의 읽어 주기 기능(브라우저 `speechSynthesis`)** 으로 소리를 낸다. 소리로 바꾸는 글은 우리가 만든 듣기 자료뿐이고, 학생의 글이나 목소리는 들어가지 않는다.
2. **듣기 자료는 자체 창작**(대화·발표·연설). 실제 인물·학교·기관 이름은 쓰지 않는다. 검수자가 한 편씩 읽는다.
3. **듣기 활동은 읽기 핵심부를 다시 쓴다.** 듣기 자료는 '지문'이고 말차례 하나가 '문단'이다(문단에 말한 사람 `speaker`). 문제 형식(고르기, 고르기+근거, 꼬리표, 문장 고르기)과 찍기 방지·보기 섞기·서버 채점·연구 데이터를 그대로 쓴다.
4. **들으며 푼다.** 처음에는 글을 숨기고 "들려주기"만 보인다. 근거는 말차례 카드(▶ 다시 듣기)를 눌러 고른다. **"글로 보기"는 언제나 열 수 있다**(소리가 안 나는 기기, 듣기에 어려움이 있는 학생). 연 학생을 불리하게 다루지 않고, 연구용으로 연 횟수만 남긴다(`transcript_views`).
5. **말하기는 채점하지 않는 준비 도구**다(토론 준비·면담 질문지). 카드뉴스와 같은 제작물 틀(`src/core/artifact`)을 쓴다. 규칙 점검으로 안내하고, 저장·제출할 때마다 안전 점검(`classifyInput`, 길이 검사보다 먼저)을 한다. AI는 쓰지 않는다.
6. **낭독·발음·입모양·시선 같은 실험 기능은 3차로 미룬다.** 크롬의 브라우저 음성 인식(`webkitSpeechRecognition`)은 소리를 회사 서버로 보내므로 결정 8(브라우저 안에서만 처리)과 맞지 않는다. 기기 안에서 도는 음성 인식(예: 브라우저용 Whisper)의 아동 한국어 정확도 검증, 학교장 승인과 보호자 동의를 갖춘 뒤 따로 설계한다.

## 1차: 듣기 활동(과제 종류 `listening`)

| 활동 id | 제목 | 성취기준 | 대상 | 자료·문제 |
| --- | --- | --- | --- | --- |
| `listen-main` | 중요한 내용 듣고 간추리기 | [4국01-01] | 3~4학년 | 발표 2편: 주제 고르기, 중요한 내용 고르기(+근거 말), 간추린 내용 고르기 |
| `polite-talk` | 상대를 생각하며 대화하기 | [4국01-04] | 3~4학년 | 상황 대화 2편: 상대의 마음·입장 고르기(+근거 말), 예의 바른 말 고르기, 알맞지 않은 말 찾기(문장 고르기) |
| `listen-infer` | 생략된 내용 추론하며 듣기 | [6국01-01] | 5~6학년 | 대화 2편: 말하지 않은 내용·까닭 고르기(+근거 말) |
| `argument-check` | 근거가 타당한지 따지며 듣기 | [6국01-02] | 5~6학년 | 연설 2편: 주장 고르기, 근거마다 '타당함/타당하지 않음' 꼬리표, 타당하지 않은 까닭 고르기 |

활동마다 자료 2편 × 문제 5~6개.

- **타당하지 않은 근거**는 초등 교과서 수준에서 다툼이 없는 것만 쓴다: 주장과 관계없는 근거, 확인할 수 없는 소문("누가 그러던데"), 한두 사례로 모두를 말하는 지나친 일반화. 값어치 판단이 갈리는 근거는 꼬리표 문제에 넣지 않는다.
- **소리 내기**: 말한 사람마다 목소리 높낮이·빠르기를 조금씩 달리한다(같은 사람은 늘 같게). 한국어 목소리가 없는 기기면 "이 기기에서는 소리를 낼 수 없어요. 글로 읽어요"라고 안내하고 글을 펼쳐 둔다.
- **연구 데이터**: 문제별 시도·힌트 단계(읽기와 같음) + 자료 들려주기 횟수(`listen_plays`), 말차례 다시 듣기 횟수(`line_replays`), 글로 보기 횟수(`transcript_views`).

## 1차: 말하기 준비 도구(제작물, 5~6학년)

### 토론 준비와 토론 타이머 — [6국01-07] (과제 종류 `debate`)
1. **논제·입장**: 교사가 정해 둔 논제 목록에서 고르거나 직접 적어 과제를 낸다. 학생은 찬성·반대 중 자기 편을 고른다.
2. **논거 나무**: 주장 한 문장 → 근거 2~3개 → 근거마다 뒷받침 자료(예: 조사 결과, 겪은 일)와 출처.
3. **예상 반론과 답**: 상대편이 할 반론 1~3개와 그에 대한 내 답.
4. **스스로 점검(규칙)**: 주장 없음, 근거 2개 미만, 뒷받침 자료 빠짐, 출처 빠짐, 반론 대비 없음, 과장 표현(카드뉴스 `findExaggerations` 재사용), 상대를 깎아내리는 말("말도 안 돼", "바보" 같은 정해 둔 목록 — "상대의 생각을 존중하는 말로 바꿔 볼까요?").
5. **토론 타이머**: 초등 토론 절차(주장 펼치기 → 작전 시간 → 반론하기 → 작전 시간 → 주장 다지기)를 차례·편·시간과 함께 보여 준다. 시간은 교사가 과제를 낼 때 바꿀 수 있다. 학생 기기 안에서만 돌고 녹음하지 않는다.
- 교사는 학생별 논거 나무와 점검 결과를 본다. 반 공유는 2차 후보.

### 면담 질문지 — [6국01-04] (과제 종류 `interview`)
1. **계획**: 면담 목적, 면담할 사람(이름 말고 **역할**로: "보건 선생님", "동네 빵집 사장님"), 면담 방법(만나서·전화·영상 통화·편지나 전자 우편 — 매체에 따라 주의할 점 안내).
2. **질문 3~8개**, 순서 바꾸기 가능.
   - 점검: '무엇·왜·어떻게·어떤·언제·누구·어디·얼마나' 없이 "네/아니요"로 끝날 수 있는 질문 → "더 자세한 대답을 들을 수 있게 바꿔 볼까요?"(바꾸지 않아도 제출 가능)
   - 상대가 대답하기 곤란할 수 있는 질문(나이, 사는 곳, 전화번호, 버는 돈 등 정해 둔 목록) → "상대가 대답하기 곤란할 수 있어요. 꼭 필요한 질문인가요?"
3. **절차 확인표**: 미리 약속하기 / 인사와 면담 목적 말하기 / 기록(녹음·사진)은 허락받기 / 들은 내용 확인하며 메모 / 고마움 전하기.
4. **면담 뒤 정리**: 알게 된 것 1~3개, 더 궁금해진 것 한 줄.
- 앱은 녹음 기능을 주지 않는다(면담 녹음은 상대 허락을 받아 학교 기기로 — 확인표에만 둔다).

## 2차(예정)

- **발표 준비**([4국01-05], [6국01-05]): 발표 짜임표(처음·가운데·끝), 자료 고르기(4단계 출처 판단과 연결), 발표 연습 타이머.
- **토의 말차례 신호등**([4국01-06], [6국01-06]): 교사 화면(교실 화면)에 띄우는 모둠 토의 진행 도구 — 말차례·의견 모으기·조정. 학생 이름 대신 번호.
- **토론 반 공유**: 교사 승인 + 정해 둔 반응.

## 3차(실험 모듈, 별도 승인 뒤)

- 낭독 유창성(기기 안 음성 인식, 교사 판정과의 일치도 연구), 발표 자세·시선(기기 안 자세 인식). 결과는 '진단'이 아니라 '연습 참고 지표'. 음성·영상은 서버로 보내지 않고 저장하지 않는다. 학교장 승인·보호자 동의 필수.

## 검수 기준(Opus)

- 듣기 자료: 들어서 이해할 수 있는 길이와 문장(3~4학년 말차례 6~10개, 5~6학년 8~14개, 한 문장 40자 안팎), 해로운 내용 없음, 실제 이름 없음, 정답이 근거 말로 하나로 정해짐.
- 근거 타당성 꼬리표는 다툼이 없을 것. 추론 문제는 글 속 말로 확인될 것.
- 말하기 도구의 점검 문구는 해요체·탓하지 않음, 제출을 막지 않는 '권유'와 막는 '꼭 필요'를 구분.
