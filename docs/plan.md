| 6 | 학생 개인정보 | **익명 계정**(학급 코드 + 번호 + 별명). 실명·이메일 저장 안 함 | 번호와 이름 대응표는 교사가 앱 밖에서 보관. 연구 데이터도 익명 상태로 분석 가능 |
| 7 | 비용·운영 | **무료 티어 중심**(Vercel·Supabase 등) + 저렴한 AI 모델 + 학생별 호출 횟수 제한 | 질문 생성은 소형 모델로 함. 학생 1인 1일 호출 상한, 학급별 월 예산 상한 설정 |
| 8 | 음성·카메라 기능 | **계획서대로 시도**(입모양·시선·자세·음성 해득 진단) | 별도의 **실험 모듈**로 마지막 단계에 개발. 영상·음성은 **브라우저 안에서만 처리**하고 서버로 보내지 않음(결정 6과 충돌 방지). 결과는 "진단"이 아니라 "연습 참고 지표"로 표시하고, 정확도를 교사 판정과 비교해 연구 결과로 보고 |
| 9 | 최종 형태 | **다른 프로그램에 병합하는 모듈**(웹·안드로이드·윈도우 모두) | 핵심부 `src/core`를 호스트 무관으로 분리. 현재 Next.js 앱은 레퍼런스 호스트로 유지. 저장소·로그인·API 키는 호스트 서버가 담당(`docs/host-integration.md`) |
| 10 | 내장 모델 | **0.5B~1B급 공개 모델을 모듈에 내장**(4비트 압축 약 400~800MB) | 2단계에서 `LocalModelRuntime` 실행기 연결(WebGPU 우선, WASM 대체). 우리 작업에 맞게 파인튜닝 |
| 11 | 외부 AI | **내장 모델 + 선택적 Claude·Gemini·ChatGPT**(API 키를 넣으면 사용) | AI 공통 연결부와 대체 순서(지정 AI → 기본 순서 → 모의 코치). 과제별 AI 선택. 같은 정책·가드레일 적용. 평가 스크립트로 AI별 대필 차단율 비교 가능 |

## B1. 재정의된 제품 포지셔닝

**한 줄 정의**
> "AI가 대신 써 주지 않는 초등 국어 글쓰기 코치" — 3~6학년 학생이 성취기준에 맞는 글을 **스스로** 계획·초고·고쳐 쓰기 하도록 질문으로 돕고, 교사는 학급 전체의 쓰기 과정을 한 화면에서 보고 개입함.

**왜 '쓰기'부터 시작하는가**

| 기준 | 쓰기 코치(추천) | 저학년 한글 해득 | 읽기 유창성(음성) |
| --- | --- | --- | --- |
| 현장 수요 | 서술형·수행평가 피드백 부담이 큼. "AI 대필" 우려에 대한 대안 수요가 있음 | 큼. 다만 정부 무료 도구(한글 또박또박)와 경쟁해야 함 | 중간 |
| 기술 난이도 | 낮음~중간(LLM + 규칙) | 중간(음성·조작 UI) | 높음(아동 STT 정확도) |
| 저작권 리스크 | 낮음(학생 자신의 글) | 낮음 | 중간(낭독 지문 필요) |
| 개인정보 리스크 | 낮음(텍스트) | 높음(음성) | 높음(음성) |
| 원본 철학과의 일치 | 핵심("사유의 외주화" 차단) | 보조 | 보조 |
| 차별성 | 높음(국내에 소크라테스식 국어 쓰기 코치가 드묾) | 낮음 | 중간 |

**대상 사용자(페르소나)**
- **주 사용자, 구매 영향자**: 초3~6 담임교사. 국어 쓰기 수업과 수행평가 피드백에 시간이 부족함. AI 도구를 써 보고 싶지만 학생이 AI로 대충 쓸까 걱정함.
- **학생**: 초3~6. 빈 종이 앞에서 막막해함. 피드백을 받아도 무엇을 고쳐야 할지 모름.
- **학부모(2단계)**: 아이의 글쓰기 성장을 보고 싶음. "AI가 대신 써 주는 건 아닌지" 걱정함.

**비즈니스 모델(가설, 검증 필요)**
1. **교사 무료(Freemium)**: 교사 1명이 한 학급에서 월 N개 과제까지 무료로 사용. 교사 커뮤니티(인디스쿨 등)를 통해 바이럴 확산함.
2. **학교 구독**: 학교 단위 무제한·관리 기능. 학교 운영비, 교육청 에듀테크 지원 사업, 학습지원 소프트웨어 목록 등재를 활용함.
3. **가정 연계(2단계)**: 학부모 성장 리포트 + 가정용 글쓰기 미션(B2C 유료).
- AIDT·KERIS 연동은 정책이 다시 바뀔 경우를 대비한 **옵션**으로만 설계함(LTI·SSO 연동 가능한 구조 유지).

## B2. MVP 기능 범위

### 포함 (In-scope)

| ID | 기능 | 설명 | 완료 기준 |
| --- | --- | --- | --- |
| F1 | 교사 과제 생성 | 학년·성취기준(예: `[4국03-01]` 문단 쓰기, `[6국03-02]` 주장하는 글)을 고르면 과제 템플릿, 평가 루브릭(3~4단계), 쓰기 단계가 자동 구성됨. 교사가 수정 가능 | 교사가 3분 안에 과제를 만들어 학급 코드나 링크로 배포 가능 |
| F2 | 학생 4단계 글쓰기 워크벤치 | ① 생각 열기(브레인스토밍 질문) → ② 계획(그래픽 오거나이저: 중심-뒷받침 문장, 주장-이유-근거 트리, 설명문 구조) → ③ 초고 → ④ 고쳐 쓰기(4단계 렌즈: 글 전체 통일성 / 문단 연결 / 문장 호응 / 낱말·띄어쓰기) | 각 단계를 저장·재개할 수 있음. 단계 이동 이력이 로그로 남음 |
| F3 | 소크라테스 AI 코치 | 학생 글 상태를 분석해 **질문과 하이라이트만** 제공함. 문장을 대신 쓰거나 예시 문단을 주지 않음. 정서 지원("처음엔 어려워도 괜찮아. 지난번에도 해냈어") 포함 | 대필 요청 차단율 ≥ 99%(B4 평가셋 기준). 학생 1회 요청당 응답 5초 이내 |
| F4 | 맞춤법·띄어쓰기 점검(규칙 엔진) | LLM이 아닌 규칙·사전 기반으로 오류 **위치만** 표시함. 고치는 것은 학생이 함("이 줄에 띄어쓰기를 다시 살펴볼까?") | 오탐률 기준치 설정 후 측정(교사 검수 샘플 200문장) |
| F5 | 교사 실시간 대시보드 | 학생별 현재 단계, 막힌 시간, AI 코치 대화 요약, 힌트 요청 횟수를 보여 줌. 학생 글에 직접 코멘트 가능. 루브릭 기반 채점 보조(AI 제안 + 교사 확정) | 교사가 30명 학급 현황을 한 화면에서 파악 가능 |
| F6 | 성장 포트폴리오 | 학생별 글 모음, 초고→최종본 비교(diff), 루브릭 점수 추이. 순위표는 두지 않음 | 학기 말 PDF로 내보내기 가능 |

## B3. 핵심 사용자 흐름

```
[교사] 과제 생성(성취기준 선택 → 템플릿·루브릭 자동 → 수정) → 학급 코드 배포
   ↓
[학생] 접속(학급 코드 + 번호, 이메일·실명 불필요)
   → ① 생각 열기: AI 코치가 질문 3개 ("요즘 가장 기억에 남는 일은?")
   → ② 계획: 오거나이저 채우기 (빈칸에 AI가 내용을 채워 주지 않음)
   → ③ 초고 작성: 막히면 [도움 요청] → 질문형 힌트 1단계 → 2단계 → 3단계(문장 시작 틀까지만)
   → ④ 고쳐 쓰기: 4단계 렌즈별 하이라이트 → 학생이 직접 수정 → 제출
   ↓
[교사] 대시보드: 막힌 학생 알림 → 코멘트 개입 → 루브릭 채점(AI 제안 + 교사 확정) → 피드백 반환
   ↓
[학생] 피드백 반영 재고쳐 쓰기(선택) → 포트폴리오 저장
```

## B4. 소크라테스 AI 코치 상세 설계

**정책(시스템 프롬프트 + 출력 검증 이중 장치)**
1. 학생 글에 들어갈 수 있는 **완성 문장을 생성하지 않음**. 허용: 질문, 오류 위치 표시, 개념 설명, 문장 시작 틀("내 생각에는 ___. 왜냐하면 ___.")
2. 한 번에 **질문 1~2개만** 함. 초등 눈높이 어휘를 쓰고 2~3문장 이내로 답함.
3. 힌트는 단계적으로 구체화함: 1단계 질문 → 2단계 생각 거리 제시 → 3단계 틀 제공. 정답이나 문단은 절대 주지 않음.
4. 정서 지원은 하되 과한 칭찬은 하지 않음. 노력·전략을 칭찬함.
5. 주제 이탈, 개인정보, 위험 신호(괴롭힘, 자해 등)를 감지하면 대화를 중단하고 교사에게 알림.

**출력 검증(가드레일)**
- 2차 검사: 응답이 학생 글에 그대로 붙여 넣을 수 있는 서술문인지 판정함(작은 분류 모델 또는 LLM 판정). 해당하면 재생성하거나 거절 문구로 바꿈.
- 응답 길이와 문장 수 상한을 둠.
- 학생 초고와 AI 응답의 n-gram 중복을 모니터링함(대필 사후 탐지).

**평가셋(출시 전 필수)**
- 대필 유도 프롬프트 300개 이상("그냥 써 줘", "예시 보여 줘", "선생님이 써 달래", 역할극 우회 등)
- 정상 도움 요청 300개 이상(질문형 도움 품질을 교사 3인이 5점 척도로 평가)
- 목표: 대필 차단 ≥ 99%, 도움 품질 평균 ≥ 4.0, 부적절 응답 0건

**모델 선택**
- 파인튜닝은 MVP에서 하지 않음. 상용 LLM API + 프롬프트 + 검증 계층으로 시작하고, 파일럿 로그가 쌓인 뒤 필요할 때 검토함.
- 비용 절감을 위해 짧은 질문 생성은 소형 모델, 루브릭 채점 보조는 상위 모델로 나눔.
- 학생 데이터를 모델 학습에 쓰지 않는 조건(Zero data retention 또는 학습 미사용 약관)의 API를 선택함.

## B5. 기술 아키텍처 (MVP)

| 계층 | 선택(권장) | 비고 |
| --- | --- | --- |
| 클라이언트 | Next.js(React) + PWA, 태블릿 우선 반응형 | 학교 크롬북·태블릿·PC 공통. 설치 불필요 |
| 백엔드 | Next.js API 라우트 또는 NestJS + PostgreSQL | 실시간 대시보드는 WebSocket 또는 Supabase Realtime |
| 인증 | 교사: 이메일·구글·네이버. 학생: 학급 코드 + 번호 + 그림 비밀번호 | 학생 실명·이메일을 수집하지 않음 |
| AI 계층 | LLM API(질문 생성·루브릭 제안) + 출력 검증기 | 프롬프트·정책 버전 관리 필수 |
| 한국어 규칙 엔진 | 형태소 분석기(예: Kiwi, MeCab-ko) + 자체 띄어쓰기·맞춤법 규칙 + 표준국어대사전 오픈 API | 상용 맞춤법 검사기는 라이선스 확인 필요 |
| 인프라 | 국내 리전 클라우드 | 학교 납품 확대 시 CSAP 등 인증 요건 재검토 |
| 로그·분석 | 이벤트 로그(단계 이동, 힌트 요청, 수정 횟수) → 대시보드 집계 | 1단계부터 xAPI 형태로 저장하면 이후 표준 연동이 쉬워짐 |

| 국어 교육 전문가(현직·전직 교사) | 1(파트타임 가능) | 성취기준 매핑, 루브릭, 오거나이저 설계, 평가셋 검수 |
| 기획·디자인 | 1 | UX(초등 눈높이), 교사 인터뷰 |

- LLM API 비용: 학생 1명이 과제 1개에 코치 호출 20~40회 × 짧은 응답 기준이면 과제당 비용은 수십 원 수준으로 추정됨(파일럿에서 실측 필요).
- 주요 고정비는 인건비임. 정부 지원사업(예비창업패키지, 에듀테크 소프트랩 실증 등) 활용을 검토함.

## B10. 바로 해야 할 일 / 결정이 필요한 사항

**결정 필요**
1. 개발 주체와 규모: 개인·교사 프로젝트인가, 스타트업인가, 기관·발행사 과제인가? (B6·B7 범위가 달라짐)
2. 첫 시장: 교사 무료 확산(B2T)인가, 학부모 유료(B2C)인가?
3. MVP 모듈: 쓰기 코치(추천)인가, 저학년 한글인가?

**다음 4주 할 일**
1. 2022 개정 국어 성취기준 원문(NCIC)으로 쓰기·읽기 성취기준 코드 표 확정
2. 실제 교과서로 3~6학년 쓰기 단원 목차 검증(원본 A4 표의 의심 항목 우선)
3. 교사 인터뷰 15명 이상: "쓰기 수업에서 가장 시간이 많이 드는 일", "AI 대필 우려", "지금 쓰는 도구"
4. 소크라테스 코치 프롬프트 v0 + 대필 유도 평가셋 100개로 기술 검증(1~2주면 가능)
5. 쓰기 워크벤치 화면 Figma 프로토타입 → 교사 5명 사용성 테스트
