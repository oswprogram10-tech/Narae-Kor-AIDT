# 3단계: 책·글 나래(읽기) 설계

작성: 2026-11-06 (계획·검수 Opus, 구현 Sonnet — `CLAUDE.md` 작업 분담)

## 원칙

1. **2단계와 같은 틀**: 규칙으로 채점(AI 없음), 찍기 방지(원리 → 힌트1 → 힌트2 → 정답 공개), 누르기 조작(드래그 없음), 서버 채점·정답 정보는 학생 기기로 보내지 않음, 문제별 연구 데이터 기록.
2. **지문은 자체 창작**(저작권 문제 없음, 결정 5). Claude가 쓰고 검수자가 한 편씩 읽는다. 실제 인물·상표·학교 이름은 쓰지 않는다. 학년 눈높이의 낱말·문장 길이.
3. **지문 하나에 여러 문제**: 학생은 지문을 읽고(화면 위쪽에 계속 보임) 아래 문제를 차례로 푼다. 문장마다 번호(id)가 있어 "문장을 눌러 고르기" 문제를 만들 수 있다.
4. **근거를 고르게 한다**: 추론·이해 문제는 답만 고르지 않고 "그렇게 생각한 문장"을 함께 고르게 해서(두 단계 모두 맞아야 정답) 찍기를 줄이고 읽기 과정을 기록한다.
5. **요약은 1차에서 AI로 채점하지 않는다**: 요약 정확도는 규칙으로 잴 수 있는 형태(문단별 중심 문장 고르기 → 간추린 글 고르기)로 먼저 재고, 학생이 직접 쓴 요약에 대한 AI 피드백은 2차에서 쓰기 코치와 같은 안전 장치 위에 얹는다.

### 문제 형식(핵심부에 추가)

- **sentence-pick**: 지문(또는 지정한 문단)의 문장 중 하나를 누른다. 정답 문장 id 목록(중심 문장이 둘로 볼 수 있는 경우 대비, 기본은 하나).
- **label-sentences**: 지정한 문장들 각각에 꼬리표(예: 사실/의견)를 단다. 모두 맞아야 정답, 틀린 문장 수와 위치는 알려 주지 않고 원리부터 안내(찍기 방지).
- **slot-paragraphs**: 문단들을 짜임 칸에 놓는다(누르고 → 칸 누르기). 칸마다 정답 문단 id 목록.
- **choice-with-evidence**: 보기 고르기 + 근거 문장 고르기(근거 정답은 여러 문장 허용 목록). 답이 맞고 근거가 틀리면 "답은 맞았어요. 지문에서 그렇게 생각한 문장을 다시 찾아봐요" 같은 별도 안내.
- 기존 **choice**(2단계 고르기)도 그대로 쓴다(간추린 글 고르기, 주제 고르기).

## 2차 설계(2026-11-06)

### 1. 내 말로 요약하기(학생이 직접 쓰는 요약) — [4국02-02]·[6국02-01]
- 1차 활동의 설명하는 글·논설문 4편(mi-cat, mi-signal, ts-lunch, ts-neck)에 '요약 쓰기' 문제를 하나씩 더한다(활동 마지막 문제).
- **AI가 아니라 규칙으로 피드백**한다(비용 0, 오프라인, 대필 위험 없음). 문단마다 검수자가 정한 **핵심 낱말 묶음**(같은 뜻의 여러 표현 허용)이 요약에 들어 있는지 본다.
  - 빠진 문단이 있으면: "3문단은 무엇에 대한 이야기였나요? 다시 읽고 한 부분으로 넣어 볼까요?"처럼 **그 문단이 무엇에 관한 것인지 묻기만** 하고 내용은 알려 주지 않는다.
  - 지문 문장을 거의 그대로 옮겨 쓴 부분이 많으면: "자기 말로 줄여 써 볼까요?"
  - 너무 길거나(지문의 절반 이상) 너무 짧으면 길이 안내.
  - 모든 문단이 들어가고 길이가 맞으면 "잘 간추렸어요" + 선생님께 제출.
- 정답/오답이 아니라 **고쳐 쓰기 반복**이다. 시도마다 '문단 반영률'(들어간 문단 수/전체)과 글자 수를 기록 → 연구 지표 "요약 정확도".
- **자유 글이므로 안전 장치를 그대로 쓴다**: 제출할 때마다 규칙 감지기(`classifyInput`)로 위험 신호·개인 정보를 확인하고, 걸리면 쓰기 코치와 같은 돌봄 안내 + 교사 알림(교사 현황 화면에 표시). 학생 글은 교사만 본다.
- AI 코치 연결(질문형 피드백)은 3차 후보로 남긴다.

### 2. 예측하며 읽기 — [4국02-03] (3~4학년)
- 지문을 **문단 단위로 차례로 펼친다**. 다음 문단을 열기 전에 "다음에 어떤 일이 일어날까요?"를 고르고(근거 문장 함께 고르기), 문단을 연 뒤 "내 예측이 맞았나요?"를 스스로 확인한다.
- 예측 문제는 앞 문단에 근거가 있는 **가장 그럴듯한 예측 하나**가 정답이고, 근거 없는 예측이 오답 보기다.
- 지문 2편(이야기 1, 설명하는 글 1).

### 3. 관점 비교하기 — [6국02-04] (5~6학년)
- 같은 문제에 대해 **관점이 다른 짧은 글 두 편**을 나란히 읽는다(예: 쉬는 시간 휴대폰 사용, 학교 텃밭 만들기).
- 문제: 각 글쓴이의 관점 고르기(근거 문장), 어느 근거가 어느 관점을 뒷받침하는지 칸에 놓기, 두 관점을 함께 고려한 해결 방안 고르기.
- 주제 2개 × 글 2편.

## 단계

1. **핵심부**(`src/core/reading/`): 지문·문제 형식·채점·검증·지문과 문제 은행, 단위 테스트. ← 첫 구현 지시서
2. **앱 연결**: 과제 종류 `reading`, 교사 과제 생성(학년별 활동), 학생 화면(지문 + 문제), 교사 결과 화면(문제별 정답률·힌트), 연구용 CSV, 브라우저 시험.
3. 이후: 학생이 직접 쓴 요약에 대한 AI 피드백(쓰기 코치 안전 장치 재사용), 질문하며 읽기([4국02-03]), 출처 판단([4국02-05], 4단계 매체와 연결), 관점 비교([6국02-04]).

## 검수 기준(Opus)

- **지문**: 사실 정보가 맞는지(설명하는 글), 학년 눈높이, 문단마다 중심 문장이 분명한지, 해로운 내용 없음.
- **문제**: 정답이 하나로 분명한지, 근거 문장 목록이 빠짐없는지, 사실/의견 꼬리표가 논란 없는 문장만 썼는지("~인 것 같다", "~해야 한다" 같은 의견 표지와 확인 가능한 사실).
- 학생에게 보이는 문구는 해요체, 학생을 탓하지 않음, 힌트에 정답이 그대로 들어가지 않음.
