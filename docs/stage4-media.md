# 4단계: 미디어 나래(매체) 설계

작성: 2026-11-06 (계획·검수 Opus, 구현 Sonnet — `CLAUDE.md` 작업 분담)

## 원칙

1. **진짜 인터넷에 나가지 않는다.** 모든 웹 페이지·검색 결과·뉴스·광고는 미리 만든 **연습용 가상 자료**다(계획서의 "샌드박스 검색 시뮬레이터"). 학생 화면에 "연습용 가상 페이지" 표시를 늘 붙인다.
2. **실제 기관·회사·사이트·인물 이름을 쓰지 않는다.** 가짜 자료가 진짜처럼 퍼질 위험(사칭)을 막기 위해 모든 이름은 지어낸다(예: "해솔시 어린이안전센터", "반짝반짝 블로그"). 상표·로고 흉내도 쓰지 않는다.
3. **2·3단계와 같은 틀**: 규칙 채점, 찍기 방지(원리 → 힌트1 → 힌트2 → 정답), 보기 순서 섞기, 서버 채점·정답 정보 비공개, 근거 고르기, 문제별 연구 데이터.
4. **읽기 핵심부를 다시 쓴다**: 가상 페이지는 '지문'에 페이지 정보(사이트 이름, 글쓴이, 날짜, 출처 표시, 광고 여부)를 더한 것으로 본다. 문장 고르기·꼬리표·보기+근거 형식을 그대로 쓰고, 검색 시뮬레이터 한 형식만 새로 만든다.
5. **판단 기준을 가르친다**: "믿을 만한가"를 감으로 고르지 않도록, 문제마다 단서(누가 썼나, 언제 썼나, 근거·출처가 있나, 광고인가, 다른 자료와 맞나)를 짚게 한다.

### 새 형식: 검색 실험실(`search-task`)
- 1단계: 목적(예: "고양이가 하루에 얼마나 자는지 알고 싶어요")에 맞는 검색어를 보기에서 고른다. 검색어마다 미리 만든 가상 결과 목록(제목·사이트 이름·한 줄 요약·광고 표시)이 있다.
- 목적에 맞지 않는 검색어를 고르면 **그 검색어의 결과가 실제로 보이고**("결과가 목적과 맞나요?" 원리 안내), 학생이 다시 고른다(찍기 방지 단계는 같다).
- 2단계: 알맞은 검색어의 결과 중 목적에 가장 맞고 믿을 만한 결과를 고르고, 그렇게 고른 단서(사이트 정보·날짜·광고 표시 등)를 근거로 누른다.
- 결과 목록과 페이지는 모두 가상이며 서버가 문제에 맞는 것만 보낸다.

## 단계

1. 핵심부(가상 페이지 정보, 검색 형식, 자료·문제 은행, 검증, 테스트) ← 첫 구현 지시서
2. 앱 연결: 과제 종류 `media`(읽기 화면을 재사용하되 가상 페이지 모양으로 보여 줌), 교사 현황·CSV, 브라우저 시험
3. 2차: **카드뉴스 만들기**([6국06-03], 학생 제작물 + 안전 점검 + 교사 공유 승인), 매체 이용 성찰 일지([6국06-04])

## 검수 기준(Opus)

- 가상 자료의 이름이 실제 기관·회사·사이트와 겹치지 않는지, 진짜처럼 오해될 표현이 없는지.
- '믿을 만함' 판단의 정답이 하나로 분명하고 단서가 자료 안에 있는지.
- 사실/과장/근거 없음 꼬리표가 논란 없는 문장인지. 기사 속 '사실'은 가상 자료 안에서 확인 가능한 것이어야 한다.
- 학생 문구 해요체, 탓하지 않음, 힌트에 정답 없음.
