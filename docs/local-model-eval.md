# 내장 AI 실측 결과 (2026-11-03)

파인튜닝하지 않은 공개 모델을 실제로 내려받아 돌린 결과입니다. 평가셋: `evals/ghostwrite.json`(대필 유도 30건 + 정상 도움 20건). 측정 환경: 클라우드 서버 CPU 4코어, 그래픽 카드 없음(학교 기기와 다름 — 아래 '한계' 참고).

## 1. 결론 요약

- **내장(오프라인)은 동작합니다.** 모델 파일과 브라우저용 실행 엔진(ONNX Runtime WASM)을 모듈 안에서 제공하고, 외부 접속을 모두 막은 상태에서 브라우저가 모델을 불러와 답했습니다.
- **안전은 지켜졌습니다.** 두 모델, 모든 측정에서 학생에게 예시 문장이 샌 경우 0건, 정상 도움 요청 과잉 차단 0건.
- **품질과 속도는 아직 수업에 쓰기 어렵습니다.** Qwen2.5 0.5B는 쓸 만한 질문을 거의 만들지 못했고, Gemma 3 1B는 질문은 괜찮지만 브라우저(CPU)에서 한 번 답하는 데 평균 36초가 걸렸습니다. → **파인튜닝과 WebGPU(그래픽 가속) 기기 측정이 다음 단계**입니다.

## 2. 설계를 바꾼 이유: '질문 중심'

처음에는 모델이 말머리(reply)·질문·살펴볼 곳(highlights)을 모두 만들게 했습니다. 실측에서 두 모델 모두

- 말머리에 내용을 대신 채워 넣거나("책이 쌓여 있으면 글을 읽기 힘들고, 책을 찾기도 어려워."),
- highlights에 예시 문장을 지어냈고("책장이 쌓여서 학습에 어려움이 생길 수 있습니다."),
- 거의 모든 요청을 '대필 요청'으로 표시했습니다(Qwen).

그래서 내장 모델은 **질문만** 만들게 하고, 말머리는 검증된 문장 은행에서, 대필 요청 판단은 규칙 감지기로 합니다(`src/core/coach/local-shape.ts`). 질문도 다음 조건을 통과해야 학생에게 보입니다: 물음표로 끝남, "~다?" 같은 가짜 질문 아님, 영어 섞이지 않음, 학생 글·질문을 되풀이하지 않음, 예시·정답 언급 없음.

Gemma 3 1B가 만든 질문 예(정상 도움 요청):

## 4. 이번에 고친 것

- 브라우저 실행 엔진 파일을 외부 CDN(jsdelivr) 대신 모듈 안(`public/ort/`)에서 제공 — 학교 방화벽·오프라인 대비
- 교차 출처 격리 헤더(COOP/COEP)로 여러 CPU 코어 사용, 계산을 작업 스레드로 옮겨 화면 멈춤 제거
- Gemma는 브라우저에서 int8 형식 사용(별도 데이터 파일 없음 설정 포함)
- 초소형 모델의 흔한 실수 처리: 질문을 문자열 하나로 줌, 괄호가 안 맞는 JSON, 템플릿("~을까요?")을 그대로 베낌, 모든 요청을 대필로 표시
- 대필 요청 규칙 감지기 보강: 평가셋 30건 중 12건 놓침 → 0건(정상 요청 오탐 0건). 단, 같은 평가셋으로 다듬었으므로 새 표현은 계속 추가해야 함
- 모델 내려받기 재시도(Hugging Face 429 대응)

## 5. 한계와 다음 단계

- **그래픽 가속(WebGPU) 미측정**: 이 환경에는 그래픽 카드가 없습니다. WebGPU가 되는 기기(최근 크롬북·노트북·태블릿 일부)에서는 훨씬 빠를 것으로 예상되지만 직접 재야 합니다 → 교사 화면 ‘내장 AI 측정’을 실제 학교 기기에서 열어 주세요(WebGPU용 파일: `npm run model:fetch -- gemma-3-1b q4f16,int8`).
- **품질**: 파인튜닝 전 Gemma 3 1B의 질문은 '쓸 만한 수준'이지만 반복·높임말·어색함이 있습니다. 학습 데이터(학년·단계·글 종류별 좋은 질문)로 파인튜닝하면 질문 품질과 속도(더 짧고 정확한 출력)를 함께 개선할 수 있습니다.
- **용량**: Gemma 3 1B int8은 1,001MB로 합의한 상한(약 1GB)에 걸칩니다. 파인튜닝 후 더 작은 형식(q4)을 브라우저가 지원하는 방식으로 다시 내보내면 줄일 수 있습니다.
- 품질 평가는 자동 지표만 썼습니다. 교사 3인이 `evals/result-*.json`의 질문을 5점 척도로 평가하면 연구용 '도움 품질' 지표가 됩니다.
